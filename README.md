# 🎵 Music Store SQL Data Analysis Project

## 📌 Project Overview

This project is a **Music Store Data Analysis project using MySQL**. It demonstrates how SQL can be used to manage relational data and generate business insights from a music-store database.

The database contains information about **artists, albums, tracks, customers, employees, playlists, invoices, and sales transactions**.

The dataset has been expanded to approximately **500 records in each table** to provide a larger dataset for SQL analysis and practice.

The main objectives of this project are:

## 🗄️ Database Structure

The project contains the following 11 tables:

| Table            | Description                                       |
| ---------------- | ------------------------------------------------- |
| `genre`          | Stores music genres                               |
| `media_type`     | Stores different media types                      |
| `artist`         | Stores artist information                         |
| `album`          | Stores album information                          |
| `track`          | Stores individual tracks                          |
| `playlist`       | Stores playlists                                  |
| `playlist_track` | Connects playlists with tracks                    |
| `employee`       | Stores employee information                       |
| `customer`       | Stores customer information                       |
| `invoice`        | Stores customer invoices                          |
| `invoice_line`   | Stores individual items purchased in each invoice |

The database uses **Primary Keys and Foreign Keys** to maintain relationships between tables. For example, albums are connected to artists, tracks are connected to albums and genres, and invoice lines are connected to invoices and tracks.

## 📊 Business Questions & Analysis

The project includes SQL analysis for several business questions.

### 1. Top 10 Customers by Spending

Identify the customers who generate the highest revenue for the business.

```sql
SELECT
    c.CustomerId,
    CONCAT(c.FirstName, ' ', c.LastName) AS full_name,
    c.Country,
    ROUND(SUM(il.UnitPrice * il.Quantity), 2) AS total_spending
FROM customer AS c
JOIN invoice AS i
    ON c.CustomerId = i.CustomerId
JOIN invoice_line AS il
    ON i.InvoiceId = il.InvoiceId
GROUP BY
    c.CustomerId,
    c.FirstName,
    c.LastName,
    c.Country
ORDER BY total_spending DESC
LIMIT 10;
```

### 5. Top 10 Tracks by Quantity Sold

Determine which tracks have the highest sales volume.

```sql
SELECT
    t.TrackId,
    t.Name,
    SUM(il.Quantity) AS quantity_sold
FROM track AS t
JOIN invoice_line AS il
    ON t.TrackId = il.TrackId
GROUP BY
    t.TrackId,
    t.Name
ORDER BY quantity_sold DESC
LIMIT 10;
```

---

### 10. Customer Spending Ranking

Rank customers from highest to lowest based on total spending.

This uses the SQL **`RANK()` window function**.

```sql
RANK() OVER (
    ORDER BY SUM(il.UnitPrice * il.Quantity) DESC
)
```

This demonstrates how window functions can be used to create rankings without collapsing the underlying analytical result.

Run the complete script to:
